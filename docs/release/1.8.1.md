# Release notes: Xarxa 1.8.1 (versionCode 8)

A packaging release on top of 1.8.0. The web app and the iOS app are unchanged; what changes is how the phone app for Android is built and where you download it. Everything since 1.8.0 is `git log v1.8.0..HEAD`.

## Why the native app is gone

Xarxa used to ship two phone apps for Android: a separate native app written in Kotlin (`android-native/`), and a Capacitor wrapper of the website (`android/`). The native app lacked development. Every feature landed on the website first, and the native app then had to be rewritten by hand to match, so it was always behind (it did not have the split view, the bus stops or the walk radii for long stretches). The website, on the other hand, can be packaged with Capacitor with very little work, and gets every feature at the same moment as the web and iOS versions.

So from 1.8.1 there is one phone app: the **Capacitor app**, packaged as an APK, and development continues on it. The native Kotlin app and its tooling are removed from `main`; its source is kept, unchanged, on the branch `native/kotlin-app` (the state of 1.8.0, commit `308e47c`) and is no longer developed.

## What's new for users

- **One app, always current.** The APK is the same app as xarxa.net and the iPhone version, so a new feature or fix reaches the phone app when it reaches the website.
- **Download link:** `releases/latest/download/Xarxa-capacitor.apk` (was `Xarxa-android.apk`). The README, the in-app download sheet and its translations point at the new name.
- **It installs next to the old app, it does not update it.** The removed native app was `com.jielei.xarxa.nativeapp`; the Capacitor app is `com.jielei.Xarxa`, so Android treats them as two apps. Install the new one, then uninstall the old one when you are happy (the old one's settings do not carry over). The Capacitor app is signed with the same sideload key as before, so it updates itself normally from now on.
- **Obtainium:** add the repository again as a new app with the APK filter `.*capacitor\.apk` (it is a different app id, so the existing entry will not switch over).
- No change to the web app, the map, the bus times or the iOS app.

## What was removed

- `android-native/` (the Kotlin app, its build, its release script, its docs) from `main`. Still available on the branch `native/kotlin-app`.
- The `Xarxa-android.apk` release asset name; every release now attaches `Xarxa-v<version>-capacitor.apk` and `Xarxa-capacitor.apk`.
- npm scripts renamed: `android:sync` is `capacitor:sync`, `android:open` is `capacitor:open`; `npm run apk` is new.

## Version places changed

- `android/version.properties`: `versionCode=8`, `versionName=1.8.1` (it was 5 / 1.4.0). This is the only version source for the APK now.
- The release script moved to `scripts/release-apk.sh`; the Play and store documents moved from `docs/android/` to `docs/capacitor/`.
- ADR-0009 has an addendum. No What's New bullet: nothing changed for web or iOS users.
- Privacy policy: not changed. The Capacitor app requests the same permissions as the website's location feature (internet, coarse and fine location).

## Not verified on a device

- The APK was built and signed on the owner's machine, and its signature checked with `apksigner`. It was installed by adb on one phone (a foldable, OnePlus/OPPO CPH2551): it launches, the map and the split view draw, the wave dots show. Bus times, location and the back button were not exercised there.
- **Differences from the old native app are untested**: the Capacitor app now draws the same interface as the website and iOS (the Material 3 skin is switched off, the theme defaults to dark), and keeps the system back button and a location rationale (ADR-0009). No one has compared it side by side with the removed app.
- The Play Store submission has not been redone; `docs/capacitor/release-checklist.md` is the path.

## Steps for the owner to publish

1. `git push origin main`.
2. `scripts/release-apk.sh v1.8.1` (builds, signs with the sideload key, attaches the two APK files), after `gh release create v1.8.1 --notes-file docs/release/1.8.1.md`.
3. Delete any leftover `android-native/` folder on your machine (untracked build output).
